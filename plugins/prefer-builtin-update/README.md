# prefer-builtin-update

Bashツール経由のsed/awk/perl/Pythonなどによるファイル置換を抑止して、
組み込みの`Edit`ツールへ誘導するClaude Codeプラグインです。
`python3 -c`や`node -e`のようなインラインスクリプトの即座実行も抑止して、
`Write`ツールによるスクリプトファイルの書き出しへ誘導します。

## インストール

このプラグインをインストールする前に、
[ncaq/konoka](../../README.md)マーケットプレイスをClaude Codeに追加してください。

Claude Codeで以下を実行します。

```text
/plugin install prefer-builtin-update@konoka
```

または`.claude/settings.json`に追加します。

```json
{
  "enabledPlugins": {
    "prefer-builtin-update@konoka": true
  }
}
```

## 提供される機能

### スキル

`prefer-builtin-update`スキルが、
ファイルの書き換えには`Edit`ツールを使うべき理由と、
大量の機械的置換のような例外の扱いをモデルへ伝えます。
インラインスクリプトを即座実行せずに、
スクリプトファイルとして書き出してから実行することも伝えます。

### PreToolUseフック

PreToolUseフックでBashツールのコマンドを監視し、
以下を検出した場合は理由付きで拒否します。
ファイルの書き換えは`Edit`ツールへ、
インラインスクリプトの即座実行は`Write`ツールによるスクリプトファイルの書き出しへ誘導します。

- `sed`と`awk`のコマンドそのもの
- `grep`の出力をファイルへ書き込む場合
  - `grep -v '...' a.hs > tmp.hs && cp tmp.hs a.hs`のようなリダイレクト
  - パイプの後ろの`tee`や`sponge`
- `cat > a.txt <<'EOF'`のような`cat`とヒアドキュメントによるファイルの作成
- `perl -i`や`ruby -i`のようなin-place編集
- `python`/`node`/`ruby`/`perl`などのスクリプト処理系のワンライナーやヒアドキュメントに、
  `open(..., "w")`や`writeFileSync`のような書き込みパターンが含まれる場合
- インラインスクリプトの即座実行
  - `python3 -c`や`node -e`のようにスクリプトの本文を引数で渡す場合
  - `python3 - <<'EOF'`や`echo '...' | python3`のように、
    スクリプトの本文を標準入力で渡す場合

sedとawkは用途を問わずコマンドごと拒否します。
モデルがsedとawkを使うのはほとんどがファイルの書き換えで、
in-place編集のフラグを封じても、
一時ファイルへ出力してから`cp`で書き戻すような方法で同じことをするためです。
`sed -n`によるファイルの範囲表示のような読み取り専用の用途も拒否されるので、
`Read`ツールの`offset`と`limit`で代替してください。

grepは検索に日常的に使うためコマンドごとは拒否せず、
出力をファイルへ書き込む場合だけを拒否します。

ファイルの作成には`Write`ツールを使ってください。
`cat`とヒアドキュメントで作ったファイルは、
`Write`ツールと違い作成前に内容を確認しにくいためです。
作業ディレクトリに置く一時的なスクリプトなども対象です。
ヒアドキュメントの内容を標準出力へ出すだけの場合や、
`git commit -m "$(cat <<'EOF' ... EOF)"`のようにコマンドへ渡す場合はファイルを作らないので素通しします。

インラインスクリプトの即座実行は、
ファイルへ書き込むかどうかを問わず拒否します。
コマンドラインに埋め込まれたスクリプトは、
シェルのクォートとスクリプト側のクォートが重なって読みにくく、
承認する人間が実行前に内容を検証しにくいためです。
`Write`ツールでスクリプトファイルとして書き出してから実行してください。
対象の処理系は以下の通りです。
書き込みパターンを含むワンライナーの検出でも同じ処理系を対象にします。

- Python: `python`と`python3`と`python3.12`のようなバージョン付きの名前、`pypy`、`ipython`
- JavaScript: `node`、`nodejs`、`bun`、`tsx`、`ts-node`、`deno`
- Ruby: `ruby`
- Perl: `perl`

スクリプトの本文を取るフラグは、
`python3 -Ic`や`perl -ne`のような結合フラグや、
`node --eval`や`node -p`のような別名も検出します。
`deno eval`も検出します。
`timeout 10 python3 -c`や`uv run python -c`のように別のコマンド越しに起動する場合や、
`nix run nixpkgs#python3 -- -c`のようにflakeの参照で起動する場合や、
`bash -c "python3 -c ..."`のように引用符の直後に書かれた場合も検出します。

標準入力については、
スクリプトファイルもモジュールも指定が無い処理系に、
ヒアドキュメントかヒアストリングかパイプが繋がっている場合を検出します。
`python3 -`のように標準入力から読むことを明示している場合も検出します。

`python3 script.py`や`python3 -m pytest`のようなスクリプトファイルやモジュールの実行は素通しします。
`cat a.json | python3 -m json.tool`のように、
スクリプトファイルやモジュールへ標準入力でデータを渡す場合も素通しします。
`python3 script.py -c config.toml`のようなスクリプトへの引数も、
スクリプトの本文を取るフラグとは取り違えません。

読み取り専用の用途(`grep`による検索や`python3 script.py`の実行など)は基本的に素通ししますが、
後述の通り誤検知はあります。

大量の機械的置換で`Edit`ツールでは現実的でない場合は、
置換処理をスクリプトファイルとして書き出してから実行してください。
スクリプトファイルの実行は検出対象外なので、
フックに拒否されずに実行できます。
拒否時の誘導メッセージでも同じ手順を案内しています。

ただし`sed -f fix.sed`や`awk -f fix.awk`のように、
プログラムだけをファイルに分けてもsedとawkのコマンドとして拒否されます。
bashやPythonなどで実行するスクリプトファイルに、
ファイルへの書き込みまで含めてください。

フック自体が失敗した場合も素通しになります。
不正な入力によるパニックなどの非0終了は非ブロッキングエラーとして扱われ、
コマンドはそのまま実行されます。
SessionStartのビルドが未完了でバイナリが存在しない場合も同様です。
`sed -i`が必ず止まることを保証するものではありません。

スクリプトファイルの実行を検出対象外にしているのは意図的な設計です。
ワンライナーと違いファイルとして残るため人間が実行前に内容を検証でき、
実行自体もBashツールの通常の承認フローを通るからです。
このプラグインはファイル改変を封じるものではなく、
検証しにくい形の改変を検証しやすい形へ誘導するものです。

## 位置づけと限界

このフックはblocklist方式なので、
書き換えパターンを網羅的に検出することは原理的にできません。
例えばgrep以外のコマンドのリダイレクトによる書き込みや、
`echo`や`printf`のリダイレクトによるファイルの作成や、
検出対象外の言語による書き換えは素通しします。
`cat`もヒアドキュメントを使わない`cat a.txt b.txt > c.txt`のような連結は対象外です。
インラインスクリプトの即座実行も、
`bash -c`のようなシェル自身のコマンド文字列や、
`php -r`のような検出対象外の処理系や、
`echo '...' | uv run python`のように別のコマンド越しの処理系へパイプで渡す場合は素通しします。
モデルの癖を矯正してリトライ往復を削減するための補助動作であり、
セキュリティ境界ではありません。

逆に読み取り専用のコマンドを誤検知して拒否することもあります。
`-i`を含む結合フラグを一律にin-place編集とみなすため、
`perl -Mstrict`や`ruby -Ilib`のようなコマンドも拒否されます。
`open('a')`のようにファイル名が書き込みモードの文字そのものの場合も、
書き込みと誤判定されます。
grepの出力のファイルへの書き込みは、
既存ファイルの書き換えか新規ファイルの作成かを区別しないため、
検索結果をファイルへ保存するような用途も拒否されます。
誤検知に当たった場合も`Edit`ツールやスクリプトファイルの実行で代替してください。

クォートやヒアドキュメント内の文字列まで完全に解析はしていません。
`echo "sed -i"`のように引用符が直接コマンド名に接する場合は、
引用符がコマンド名と同じ単語にくっつくため誤マッチしません。
しかしクォート内でも`echo "a; sed -i x"`のように、
`;`や`&&`の後へコマンド名が現れる場合はそこがトークン境界になるため誤検知します。
一方で書き込みパターンの探索はコマンド文字列全体に対して行うため、
`rg 'File.write' src/ && ruby -e 'puts 1'`のように、
別コマンド側に書き込みパターンの文字列がある複合コマンドは誤検知します。

インラインスクリプトの即座実行の検出は、
別のコマンド越しの起動を拾うために処理系の名前がコマンド名の位置にあるかを見ません。
クォートも解釈しないので、
`git commit -m "reject python3 -c one-liners"`のような文章の中の言及や、
`rg python -c`のように処理系の名前を検索語にして後ろへフラグを書いた場合は誤検知します。
パイプで本文を渡しているかの判定だけはシェルの引用符を解釈しているので、
`rg "node|python|ruby"`のような検索パターン内の`|`をパイプと取り違えません。

sedとawkとgrepはコマンド名の位置にある場合だけを対象にするので、
`grep -rn sed src/`の検索語や`git commit -m "replace sed"`のメッセージ中の単語は誤検知しません。
コマンド名の位置は、
先頭と`;`や`&&`や`|`や`(`や改行の直後に加えて、
変数代入や`env`や`sudo`や`xargs`などの後ろと、
`find -exec`の後ろとして判定します。
`sudo -u root sed`のようなオプションの値の後ろにあるコマンド名は見逃します。
この判定もクォートを解釈しないので、
`echo "a; sed"`のように区切り文字の後ろに現れる場合は誤検知します。

grepの出力先の判定はシェルの引用符を解釈しているので、
`grep 'a > b'`のような検索パターン内の`>`をリダイレクトと取り違えません。

## 実装

フック本体はRustバイナリ`prefer-builtin-update`です。
Bashツール毎に呼ばれるため起動コストを抑える目的で、
ネイティブバイナリで実装しています。

複合コマンド(`cd foo && sed -i ...`)やヒアドキュメントも検査対象にするため、
コマンドのprefixによる絞り込みはせずに全てのBashツール呼び出しで起動します。

SessionStartフックの`hooks/build`が初回セッションで`cargo build --locked --release`を走らせ、
`target/release/prefer-builtin-update`を生成します。
ビルド成果物はGitで追跡せず、
プラグイン更新時は再ビルドされます。

よって利用するには`cargo`(Rust toolchain)が必要です。

OpenCode連携ではスキルのみが機能し、
フックは機能しません。
