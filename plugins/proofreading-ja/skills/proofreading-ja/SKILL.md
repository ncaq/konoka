日本語の文章を校正し、見つけた問題をその場でファイルを編集して直します。
著者の意図と文体を保ったまま、読者にとって読みやすく正確な文章にすることが目的です。

# 対象の特定

ユーザが校正する対象を、スキルの引数や会話の中で指定している場合は、その対象を校正します。

指定が無い場合は、Gitのコミットログから最新の記事のファイルを特定して校正します。

```bash
git log --oneline --name-only -20
```

最近変更されたファイルの中から、記事のファイルを探してください。
記事を置くディレクトリや命名規則はプロジェクトごとに違うので、パスと内容から判断します。
記事を特定できない場合は、推測で編集を始めずに、ユーザに対象を尋ねてください。

# 校正の観点

最初に対象の全体を読み、主題と目的、想定する読者、著者の文体、全体の構成を掴みます。
その上で、以下の観点で問題を探します。

- 誤字脱字: 漢字の誤変換、タイプミス、送り仮名の誤り、助詞などの脱字。
- 文法と表現: 主語と述語の不一致、係り受けの誤り、冗長な表現、重複表現、不自然な言い回し。
- 読みやすさ: 長すぎる文、接続詞の過不足、不適切な段落の区切り、専門用語の説明不足。
- 表記の統一: 同じ語の表記揺れ、数字の表記(半角と全角、漢数字)の揺れ、記号の使い方。
  記号はプロジェクトの指示に従い、半角を優先します。
  全角の括弧は使わず、半角の括弧に直します。
- 技術的な正確性: コードブロックの構文エラー、コマンド例の誤り、見出しレベルの誤り、技術用語の誤用。

# 修正

見つけた問題は、提案として並べるだけにせず、その場で`Edit`ツールでファイルを編集して直します。
対象がファイルではなく会話に貼られた文章の場合は、
ファイルを編集する代わりに、校正後の文章を応答に書きます。

校正は著者の文章を整える作業であり、書き直しではありません。

- 著者の文体を保ち、文の意味を変えないようにします。
- 著者の意図を判断できない箇所は、修正せずに報告します。
  誤りなのか意図した表現なのかが分からない箇所と、何を言おうとしているのかが分からない箇所です。
- 大幅な書き換えが必要な箇所は、修正した理由を報告に含めます。

修正した後は対象の全体を読み直して、
修正によって新しい問題が生じていないか、見落としがないか、文章の流れが自然かを確かめます。
直す箇所が見つからなくなるまで、校正と読み直しを繰り返してください。

# 完了報告

修正が全て終わったら、以下を報告します。

- 校正したファイルのパス
- 主な修正内容と、その具体例
- 大幅に書き換えた箇所と、その理由
- 著者の意図を判断できず、修正しなかった箇所
- 著者への提案や注意点(あれば)
